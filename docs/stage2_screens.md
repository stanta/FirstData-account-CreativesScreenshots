# Нужно детально и всесторонне спланировать изменение флоу работы бота:

1. после шага выбора площадки и типа баннера добавить шаг, на котором загружается готовый скриншот площадки (убрать блок обращения площадки и скачивания страницы) с рекламой и далее шаг загрузки креатива , который нужно вставить флоу без изменений
2. нужно проанализировать вставленный скриншот при помощи ИИ (Gemma LLM, API доступ по логину и паролю можно взять код из проекта validator-ai) и определить
   2.1 Запрос 1 - область рекламного баннера, который надо заменить (по приведенным примерам на этой площадке и типу баннера )
   2.2 Запрос-2 область открытой ссылки на целевую страницу ( по приведенным примерам по этой пложадке)
   2.3 вернуть координаты рекламного баннера на картинке
3. внести креатив на скриншот
   3.1 вставить присланный креатив средствами Pillow
   3.2 вставить область со ссылкой на целевой сайт и utm -метками средствами Pillow
   3.3 вставить сведения о рекламе (отдельный модуль "реклама", как на примерах - по типу площадки)
   3.4 сохранить промежуточный результат в tmp
   3.5 вернуть результат пользователю в телеграм-бот

4. НЕ НУЖНО проверять работу целевого сайта, просто поменять строку в области со ссылкой на целевой сайт и utm-метками

## Аналитический бриф

Цель изменения: перепланировать текущий flow [`reports_ad`](reports_ad) так, чтобы ПОСЛЕ шагов загрузки/открытия live-площадок бот принимал готовые скриншоты площадок с рекламой, далее принимал креатив, с помощью ИИ определял области для замены на изображении, заменял рекламный блок и область перехода средствами Pillow, добавлял сведения о рекламе и возвращал пользователю готовый результат.

Источник постановки: пользовательское уточнение в текущем диалоге; текущая реализация и проектный журнал находятся в [`reports_ad/AGENTS.md`](reports_ad/AGENTS.md), текущий proof-flow — в [`reports_ad/reports_ad/proof.py`](reports_ad/reports_ad/proof.py), Telegram-flow — в [`reports_ad/reports_ad/bot.py`](reports_ad/reports_ad/bot.py), примеры площадок — в [`reports_ad/docs/examples/FD -- Примеры скриншотов/площадки.txt`](reports_ad/docs/examples/FD%20--%20Примеры%20скриншотов/площадки.txt).

### Финанльный  целевой flow v2

   Пользователь запускает заявку в Telegram, 
1. выбирает рекламную систему и 
2. вид баннера
3. Пользователь загружает готовый скриншот площадки с уже размещенной рекламой, (убрать блок  перехода на сайт площадки и его скачивания) .
4. Система валидирует скриншот: PNG/JPEG, размер файла до 1 МБ, читаемость изображения.
5. Пользователь загружает PNG/JPEG-креатив.
6. Система валидирует креатив и определяет/подтверждает тип баннера на основании креатива и скриншота, PNG/JPEG, размер файла до 1 МБ.
7. Пользователь вводит landing URL.
8. Пользователь вводит UTM-строку.
9. Система отправляет скриншот и контекст в Gemma/(алгоритм подключения аналогично из @validator-ai) для определения областей.
10. Система получает координаты области баннера и области ссылки/landing-зоны.

11. После подтверждения система средствами Pillow заменяет баннер, меняет строку landing URL + UTM, добавляет модуль «Реклама», сохраняет промежуточный и финальный результат в [`reports_ad/tmp`](../tmp).
12. Система отправляет финальный результат пользователю в Telegram.
