# ВК: карточка по эскизу v1 (Telegram)

**Статус:** реализация в ветке feat/vk-card-mask-bot-20261015.
**Профиль:** визуальный макет по предоставленному эскизу, **не** скриншот опубликованной рекламы ВК.
**Оригиналы:** чистый эскиз 548×554 и изображение с красной разметкой 1236×1035 предоставлены пользователем 15.10.2026. Исходные файлы не встраиваются в маску.

## Поля

| Место карточки | Источник | Параметр |
| --- | --- | --- |
| Центральный креатив | PNG/JPEG пользователя | creative |
| Логотип в круге | отдельный PNG/JPEG пользователя | vk_logo |
| Заголовок в шапке | текст пользователя | vk_header_text |
| Текст под кнопкой, включая абзацы | текст пользователя | vk_body_text |
| Подпись кнопки | выбор из versioned каталога | vk_cta_id |
| Возраст в строке «Реклама · N+» | явный ввод и подтверждение | minimum_age |
| Фон карточки, меню, круг, CTA-фон, стрелка | маска/рендерер площадки | параметры v1 |

Единственный подтверждённый CTA: «Подробнее». Новые варианты допускаются только после согласования; никаких URL, UTM, favicon или названий сообщества в этом сценарии нет.

## Telegram FSM

Старт → ВК → «Карточка с кнопкой — 1080×607» **или** «Карточка с кнопкой — 600×600» → креатив → логотип → заголовок → многострочный основной текст → CTA → минимальный возраст 0..99 → предпросмотр → адресное редактирование/подтверждение → PNG-документ.

«◀ Назад» и «Отмена» доступны при заполнении. Каждое исправленное поле увеличивает revision и аннулирует прежний PNG. При подтверждении проверяются revision и SHA-256 preview, отправляется сам сохранённый файл без повторного рендера. При ошибке отправки файл остаётся доступным для повторной попытки; после успешного завершения, отмены или 30 минут бездействия он удаляется. История в БД не создаётся.

## Маска и геометрия

| Область | Границы в итоговой ширине 1080 |
| --- | --- |
| Верхняя панель | y=0..161 |
| Креатив 1080×607 | x=0..1079, y=162..768; рекомендуемый файл 1080×607 |
| Креатив 600×600 | квадратная область x=0..1079, y=162..1241; рекомендуемый файл 600×600, вписывается в 1080×1080 |
| Кнопка 1080×607 | x=0..1079, y=769..857 |
| Кнопка 600×600 | x=0..1079, y=1242..1330 |
| Текстовый блок 1080×607 | y>=858, минимум 233 px и динамический рост |
| Текстовый блок 600×600 | y>=1331, минимум 233 px и динамический рост |

Входной креатив другого размера вписывается пропорционально с белыми полями; не растягивается и не обрезается. Минимальная высота итогового PNG: 1091 px для 1080×607 и 1564 px для 600×600; ширина обеих карточек 1080 px, предельная высота 4096. Для квадратного формата используется тот же PNG-оверлей шапки площадки: рендерер переносит нижний участок маски после квадратного креатива, не растягивая прозрачные и непрозрачные элементы. Шрифт: установленный в Docker DejaVu Sans. Заголовок не переносится и не усекается: слишком длинный отвергается. Основной текст переносится с сохранением явных пустых строк. CTA определяется по квантованной палитре креатива с проверкой контраста белой надписи >=4.5:1; это **собственная воспроизводимая аппроксимация**, а не подтверждённый закрытый алгоритм площадки.

**Версионированные ресурсы:**

- docs/design/vk/card-v1.svg — редактируемый исходник оформления;
- docs/design/vk/card-square-v1.svg — редактируемый эскиз квадратной компоновки (использует общую PNG-маску);
- reports_ad/data/masks/VK/card-v1.png — PNG-маска; область креатива и кнопки полностью прозрачные;
- reports_ad/data/masks/VK/layout-v1.json — геометрия широкого креатива;
- reports_ad/data/masks/VK/layout-square-v1.json — геометрия квадратного креатива;
- reports_ad/data/masks/VK/card-v1.png — общая маска площадки для обеих карточек: квадратный вариант собирается без изменения исходного PNG;
- reports_ad/data/masks/VK/cta-options-v1.json — разрешённые подписи;
- reports_ad/vk_card.py — Pillow-композиция и валидация;
- reports_ad/vk_flow.py — шаги диалога, редактирование и доставка.

## Тесты

Проверки без обращения к внешней сети:

    python -m pytest -q tests/test_vk_card_rendering.py tests/test_vk_bot_flow.py
    python -m pytest -q -m "not telegram_e2e and not network" tests

Живой Telegram E2E:

    TELEGRAM_E2E=1 python -m pytest -q -m telegram_e2e tests/e2e/test_vk_card_flow.py

Живые E2E требуют отдельного тестового токена и пользователя; повторно использовать production polling-токен нельзя. Шрифтовая и визуальная идентичность эталону требует отдельного ручного утверждения: исходный шрифт и правила алгоритма CTA по одному скриншоту не подтверждаются.
